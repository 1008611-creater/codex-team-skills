# 念念发布治理

## 目的

让开发、验收和生产发布使用同一套可追溯的交接记录，避免“代码已完成但线上仍是旧版本”。

## 角色边界

- 开发线程：实现、测试并生成候选包；不得切换正式版本、重启生产服务或宣称已上线。
- 验收线程：按需求和真实站点行为独立验证；只能记录通过、失败或阻塞，不替开发修代码。
- 发布线程：唯一允许审核候选包、切换正式版本、重启服务和回读正式站点的线程。
- 需求线程：维护需求、非目标和验收条件；不把聊天结论直接当成发布事实。

## 交接要求

每次交接必须包含：

1. `project_id` 与项目根目录。
2. 候选包路径和源代码提交。
3. 自测命令与结果、未覆盖风险。
4. 回滚点和正式发布前的预期回读地址。

## 发布门

发布线程必须先核对 [niannian-release-baseline.md](niannian-release-baseline.md)，再执行正式切换。只有生产服务状态、正式网页、关键静态资源和真实业务回读全部通过，才能把候选包登记为当前版本。

## 禁止事项

- 不使用聊天里的“已完成”、接口成功或本地预览替代正式回读。
- 不把密码、令牌、Cookie、接口密钥或浏览器会话写入团队仓库。
- 不让开发线程直接改正式版本指针。
